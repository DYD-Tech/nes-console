# 模拟器核心与宿主

分两块：**核心**（别人写的 NES 模拟器，编成 wasm）和**宿主**（我们写的几百行 JS，
负责把核心接到浏览器上）。宿主只做 libretro 规定的那件事，不含任何 NES 逻辑。

## 为什么是这个组合

- **不用 jsnes**：纯 JS 的 jsnes 慢不是问题，**认板卡**才是。国产卡带用的 GNROM / WS / NJ /
  MMC3 变体它没实现，`热血格斗`、`金庸群侠传`、`重装机兵` 这几款直接加载不了。
  fceumm 是 libretro 生态里最成熟的 NES 核心，各家板卡都实现过，这几款都能跑。
  这是换核心的唯一动机。
- **不用 EmulatorJS / Nostalgist**（都评估过）：它们各自打包了一整套前端
  （自带菜单、按键映射、存档界面），而本站的界面是 Ozone 风格的屏幕内系统，
  套进去等于把已有界面推倒；核心的下载、体积、启动时序也归它们管，
  而我们要的是「只带一个 NES 核心 + 一层薄宿主」，可控且可审。
- **核心自己编**：上游 fceumm 的 emscripten 分支产出的是给 RetroArch 整包静态链接的 `.bc`，
  浏览器里用不了独立模块的形态，所以用 emsdk 直接编源码（`scripts/build-core.cjs`，
  对标的是核心自己的 `Makefile.common` / `Makefile.libretro`，三处有意不同都写在文件头注释里）。

兼容性以核心为准，不单独维护一份「支持列表」：fceumm 认不认就是产品认不认。
各板卡实测结果（帧数、SRAM、画面）在 `agent-workspace/note-fceumm-wasm.md` 的探针表里。

## 重编核心

```bash
npm run build:core                     # 默认取 ~/emsdk
EMSDK_DIR=/path/to/emsdk npm run build:core
```

只有换核心版本时才需要跑；产物 `public/cores/` 已在仓库里，CI 不需要 emsdk。
编译产物旁边会写一份 `fceumm_libretro.build.json`，记下源码仓库、commit、宏开关和工具链，
拿到 dist 里的 wasm 也能查它是从哪份源码编的。

## 宿主实现了哪部分 libretro

`src/lib/nes/libretro-host.js`。常量与结构体布局都从仓库内那份
`third_party/libretro-fceumm/src/drivers/libretro/libretro-common/include/libretro.h` 查得，
不是凭记忆写的，出处以注释形式钉在代码里。几条必须知道的：

- **ROM 要落进虚拟文件系统再传路径**：fceumm 的 `need_fullpath = true`（libretro.h 约定的
  核心侧选项），所以 `FS.writeFile('/game.nes', bytes)` 之后只传路径，`retro_game_info` 的
  data/size 留 0。
- **像素格式**：`RETRO_PIXEL_FORMAT_XRGB8888`，小端在内存里是 **B,G,R,X**，
  而 `ImageData` 要 R,G,B,A → 逐行按 `pitch` 取，并换 R/B 通道（不能整块 memcpy）。
- **帧率按核心报的走**：`retro_get_system_av_info` 的 timing 里 fps 在前、sample_rate 在后
  （两个 double，因对齐落在结构体偏移 24）。NTSC 报 60.100，
  50 Hz 的那类板卡报 **50.007** —— 写死 60 会跑快。
- **内存增长**：编译时开了 `ALLOW_MEMORY_GROWTH=1`，堆视图（`HEAPU8` 等）会换对象，
  所以宿主每次访问都重新取，不缓存成局部变量。
- **按键按单个 id 回答，能力协商一律回 false**：`GET_INPUT_BITMASKS` 回 true 等于承诺
  「核心可以用 `id = RETRO_DEVICE_ID_JOYPAD_MASK`(256) 一次取回全部按键的位掩码」
  （libretro.h:1793-1807）。我们给不出，就必须回 false；这里回错，fceumm 就每帧只查 256、
  拿到的永远是 0，表现为**游戏完全收不到按键而且零报错**（详见踩坑文档）。
  核心每帧实际查 19 次：两个手柄各按它的 `bindmap` 查 9 项
  （NES 没有 Y/X 位，所以 libretro 的 id 1、9 从不被查），0 号手柄再查一次 L2 做换色。

## 声音：AudioWorklet + 一条深度反馈

对标 RetroArch 自己的 Web 端口 `audio/drivers/audioworklet.c`，四条语义照抄：
跑帧侧只当生产者；实时线程里不等待；取干就补静音并计数；写不下就丢最旧并计数。

一处必须偏离：它用 `SharedArrayBuffer` 上的单生产者环，而本站没有跨源隔离
（无 COOP/COEP 头，GitHub Pages 上开这个要连全站一起改），`SharedArrayBuffer` 造不出来。
所以环改成 worklet 私有的，跨线程用 `port.postMessage` 传 Float32Array（transferable，零拷贝），
深度/欠载/丢弃由 worklet 每 32 个 quantum（85 ms）回报一次。

**深度反馈不是可选项**：跑帧按墙上时钟、消费按声卡时钟，两边差 0.9% 时
15 秒就能把队列堆到 140 ms 开始丢音（实测丢 5248 帧）。
所以拿回报的队列深度做比例控制，把每帧时长微调 ±2%（`_syncSpeedToAudio`）。
另外开局要等 worklet 第一次回报之后再跑帧，否则一上来就堆满。

**常年保持的深度是 2048 帧（约 43 ms @48k）**，这个数是量出来的：定 1024（21 ms）时，
主线程一次两帧的停顿就比整个缓冲还长，测过的几款卡带都有 0.3%~1.4% 的样本要靠补静音填
（听感是偶发「嗒」一声）。缓冲余量要按**生产侧能抖多久**定，不是按想要的延迟定；
这 21 ms 相对浏览器自己的输出延迟（实测约 48 ms）不是主角。用
`node agent-workspace/check-audio-drift.cjs` 看「每秒断音」这条曲线验收。

**音频出口可能被浏览器关掉，那不是启动失败**。`audioWorklet` 只在**安全上下文**
（https、`localhost`、`127.0.0.1`、`[::1]`）暴露，手机用局域网 http 地址打开本站就没有
（W3C Secure Contexts 把 AudioWorklet 列在 only-secure 清单里）。`_ensureAudio()` 先探测再建，
拿不到就关掉刚创建的 AudioContext、把原因写成人话存进 `host.audioBlocked`，游戏照常跑、只是没声音；
`app.js` 把这句原因并进运行提示（「非 HTTPS 地址下浏览器禁用了网页音频，已静音运行
（改用 https 或 localhost 访问即有声音）」）。跑帧侧不用改：`_speed` 本来就是 1，
`_flushAudio()`/`stop()` 对 `workletNode`/`audioCtx` 早已判空。
用 `node agent-workspace/repro-insecure-context.cjs http://<局域网地址>:7890` 复现这条路径。

## 存档格式：与桌面 RetroArch 互通

- **即时存档**写的是**不压缩的 RASTATE 容器**（`src/lib/nes/rastate.js`），
  格式对标 RetroArch `tasks/task_save.c`：`"RASTATE"` + 版本字节 1，
  块 = 4 字节 ASCII ID + uint32LE 长度 + 载荷补零到 8 字节对齐，末尾 `END ` 块。
  中间那块 ID 为 `MEM `，装的就是核心的序列化数据。
  这样这个文件拖进桌面 RetroArch 能读，RetroArch 存出来的档这里也能读
  （读侧照 RetroArch 的做法：没有 `RASTATE` 魔数就当成裸的核心数据）。
- **电池 RAM**（`retro_get_memory_data/size(RETRO_MEMORY_SAVE_RAM)`）单独存一张表，
  原样导出就是 RetroArch 的 `.srm`。没有电池 RAM 的板卡这一项是 0 字节，不是错误。
- 落库与界面行为见 [`游戏库与存档.md`](游戏库与存档.md)。

## 核心自己也会发消息

libretro 的 `SET_MESSAGE` 环境回调就是「请前端显示一行短消息」，宿主的 `_environment`
收到后原样转给 `onStatus`，界面是一条 toast。宿主自己额外发两条：载入成功
`已加载: 热血格斗（60.10 fps / 44100 Hz）`、失败 `加载失败: 热血格斗` ——
前者是「等了这一下到底发生了什么」的反馈（启动一款游戏要几百毫秒，不说一声就像卡住）。
核心那边只有少数情况会开口（`FCEUD_DispMessage`：改了区划选项报 `System: NTSC/PAL`、
缺 Game Genie / FDS BIOS 报缺文件，`cart.c:401` / `fds.c:688`），
都是英文短句，跑普通 `.nes` 遇不到，所以界面里看到的仍然是中文。

# 控制与手柄

「控制管理」这个分类下的四件事：改键盘绑定、虚拟手柄显隐、拖动摆放、复位。
所有值存在 localStorage 的 `controls` 子树里，和 CRT、音量这些设置走同一套读写
（`settings-manager.js`）。

## 按键映射：存的是「动作 → 键」

界面上列的是 13 个动作（方向、A/B/X/Y、SELECT/START、快速存/读、呼出菜单），
每行右边显示它当前绑的是键盘上哪个键。X/Y 两行也照常列（按得动、能绑定），
但界面功能不挂在它们上面（理由见 README「操作」一节）。存储结构是「动作 → 键」的一张表，
而不是「键 → 动作」：

```js
controls.keyMap = { A: 'KeyX', B: 'KeyZ', START: 'Enter', ... }
```

- **为什么是这个方向**：一个动作同一时刻只有一个键，改绑就是 `keyMap[A] = 'KeyJ'`
  一次赋值；反向表（运行时按键要查它代表哪个动作）由 `buildKeyMap()` 现算，不落盘，
  所以不存在两份数据对不上的可能。RetroArch 的配置模板也是同样的方向
  （`retroarch.cfg` 键盘段：`input_player1_a = x`、`input_player1_b = z`），
  本项目默认值与它一致。
- **键名用 `KeyboardEvent.code`**（物理位置），不用 `key`：`key` 受输入法、大小写、
  键盘布局影响，法语键盘上同一个物理键是别的字母。
- **按下即换 + 抢键自动让位**：`setBinding(action, code)` 会把已经占着这个键的别的动作解绑，
  并把它返回给调用方，toast 里写清楚「START 已绑到 J（快速保存 已解绑）」，
  不让用户去猜为什么某个键突然失灵了。
- **等按键的状态放在 `InputManager` 里**，不放在界面里：界面的按键监听会先把方向键当成
  「移动光标」消费掉，谁先拿到事件决定这次按键算改绑还是算导航，这类顺序依赖很脆。
  `beginKeyCapture(cb)` 在 InputManager 的最前面拦一道，捕获期间不派发任何动作，
  回调拿到 `code` 就结束。
- **Esc 保留作「取消改绑」、Backspace 保留作「清空该动作」**，所以 MENU 这个动作不允许绑到 Esc
  （菜单里那一行有说明）。捕获态的底栏图例会把这两个键写出来，不用用户猜。
  清空为什么放在捕获态里而不是单独立一个键：改绑本来就是键盘动作，用键盘上的键完成它最顺。
- **解绑存空串 `''` 而不是 `null`**：设置读回来要和默认值做类型比对再深合并，
  `null` 的类型是 `object`、和默认值的 `string` 对不上，会被当成脏数据丢掉，
  表现为「解绑没存住，刷新又回来了」。界面上空串显示为「未绑定」。

## 虚拟手柄：整块三档 + 单键显隐

`controls.padMode` 三档循环：自动（只在触摸设备上显示）→ 始终显示 → 隐藏。
`controls.padKeys` 再决定方向键、A、B、中间的 AB、X、Y、SELECT、START 各自露不露。
这两件事都由 `touch-layout.js` 的同一个 `apply()` 落地，启动时和每次改设置后都调它，
所以「改了立刻生效」和「刷新后还是那样」不会走岔。对标 RetroArch 只有覆盖层整体开关
（`input_overlay_enable` 等），显隐粒度到单个按键是本项目的需要。
方向键是**整组**开关：只留「上/下」的十字键没有意义。

## 十字方向键：四片软拨片，按扇区判定方向

触摸手柄的方向键不是一个方向一个圆钮，而是**四片一模一样的拨片**，尖头都指向同一个中心、
彼此留一道缝（`index.astro` 里一个 `.touch-dpad`：SVG 外形 + 铺满的命中层 + 四个臂格子）。
一片的形状定义一次放在 `<defs>` 里，其余三片靠 `rotate(90/180/270 50 50)` 摆位，
所以四片不可能长歪。每片是「方块 + 三角」拼成的短锥：外端一条扁弧接一段直的侧边，
再直直收成一个圆头尖；接缝处全部倒圆，中间没有分隔线。

按下哪个方向由 `input-manager.js` 的 `attachTouchDpad()` 按「指针相对十字中心的角度」算：

- 离某个臂不超过 ±22.5° → 只给那个方向（拇指按歪一点不会出斜向）；
- 落在两臂中间（四角那块）→ 同时给两个方向，也就是**斜向**；
- 中心的方形区域是**死区**（边长为十字的 16%），按了不算任何方向；
  四片的尖头收在离中心 11% 处，正好在死区外沿 —— 中间那道空缝就是死区，
  按了没反应的地方是看得见的，所以不另画中心点；
- 按住滑动可以连续换向，两根手指同时按取并集。

亮的是整片：按下哪个方向，`.touch-dpad` 上的 `data-active` 就带上它，对应那片整片变色。

**对标**：判定规则对标 Microsoft《Touch Adaptation Kit》的方向键条目 —— `deadzone` 明确是
轴向方形，`interaction.activationType` 默认 `allowNeighboring`（按在相邻两臂之间同时触发两个方向）；
「一整块按扇区、按下亮对应的臂」对标 RetroArch 默认覆盖层的 `dir-8-way`。
拨片的具体轮廓不是从哪个库里抄的，是照一张真机方向键照片画的：四片同形、方块接三角、
四角与尖头都倒圆、四尖朝心留一道缝。检索过现成实现（touch d-pad 斜向 / clip-path cross /
RetroArch overlay / EmulatorJS 手柄），没找到可直接采用的成品，多为四个按钮拼接的写法，
所以判定逻辑自研，DOM 结构照上面两条规范设计。

四个臂的方位不写死在 JS 里：臂元素（`.touch-up` 等）用 `data-action` 声明自己代表哪个方向，
`attachTouchDpad` 按下时现量它们的位置算方位角 —— CSS 改了排布、摆放模式拖过位置，判定都跟着变。
斜向是真的送进模拟器两个键位（`verify-dpad.cjs` 拿它和键盘同时按 ↑+→ 的结果逐位比对），
不是只亮个颜色。

## 一整套手柄只有三种形

淡底、描边色、描边粗细、按下的亮青这四样定义在 `--pad-surface / --pad-line / --pad-line-w /
--pad-press / --pad-press-line` 上，拨片和 `.touch-btn` 都读它们，所以手柄上那七颗按钮和
方向键是一套东西：

- **四片软拨片**（方向键）
- **圆片**：X/Y/A/B 加簇心那颗 AB，五颗都是 48px，靠 `.touch-btn` 的 `border-radius: 50%`
- **扁长条**：SELECT/START，56×28 的胶囊（`border-radius: 999px` 让两端收成半圆，
  真实手柄上这两颗就是细长条）。28px 低于「触摸目标不小于 44px」的建议值，是有意的取舍：
  这两颗按得少，而且摆放模式下整块手柄还能拖到顺手的位置；四条臂和五颗圆键都保住了 48px。

两块各管一个拇指：**左手**是十字键 + 它下面的 SELECT/START（`.touch-dpad-group`），
**右手**是五颗圆键围出的正方形簇（`.touch-actions`）。摆放模式按这两块拖。

**五颗圆键同尺寸，间距就得反着算**：AB 要摆在正中间、又要和四颗角键一样大（48px），
四颗角键就得被推开 —— 相邻键圆心相距 84px（`gap: 2.25rem` = 36px 加一颗键 48px），
簇心到任一颗键圆心 84/√2 ≈ 59.4px，减掉两个半径 48px，四边各留约 11.4px 缝。
这个间距顺带让整簇正好 132px 见方，**和左边的十字键同宽**，左右两块的视线重量才对得上。
DOM 上 `.touch-actions` 自己就是那个 2×2 正方形，AB 靠 `left/top: 50%` 居中在它上面 ——
这块的几何中心就是四颗键的几何中心，不用写魔法数字。

两块都是底对齐，右块用 `margin-bottom: 2.45rem` 补回左列在十字键下面多出来的那一排
（键行距 0.7rem + 扁条高 1.75rem），十字键中心和五键簇中心才落在同一条水平线上 ——
拇指同时按左右两组时不用一只手抬着。

行为上 AB 不是新动作：`data-action="A B"` 写了两个动作，按住就是 `A` 和 `B` 两个动作各自按下
（`bindTouchControls` 按空格拆属性值），所以核心每帧取到的是 A、B 两个位同时为 1，
和两根手指分别按住 A、B 完全一样。

**取景框贴着拨片外缘，十字的顶边才压得平 X/Y 的顶边**：拨片路径的最外缘在 4.3 单位
（顶部那条扁弧的贝塞尔中点），照 0~100 取景，画出来的十字比 132px 的格子小一圈、顶边低 5.7px ——
两块盒子明明齐平，看着却是方向键矮一截。所以 `viewBox` 内缩到 3.24 起、边长 93.52，
让描边外缘正好落在格子边上：内缩量 = 4.3 − 半个描边，边长 = 91.4 + 描边，
再要求描边折算成 px 等于 3，两个条件联立就是这一对数。
拨片描边写的是 viewBox 单位而取景框不是整块 100 单位，所以 1 单位 = 132/93.52 ≈ 1.411px，
2.13 单位 ≈ 3px，和 `--pad-line-w` 等粗 —— 改了臂宽或边框粗这两个数都要重算
（`verify-dpad.cjs` 里「按钮边框与拨片描边等粗」「方向键画出来的顶边和 X/Y 的顶边齐平」
钉的就是这两个数，判的是含描边的可见边）。

## 自由摆放按键

进入摆放模式：菜单先关掉（菜单在屏幕里，手柄在屏幕外，开着菜单既看不见也拖不到），
按住**整组**（十字键区 / 功能键区）拖动，松手即保存。

- **存的是「占视口宽/高的比例」，不是 px**：换设备、转屏之后 px 值会把按键顶到屏外，
  比例值仍是同一个相对位置。RetroArch 的覆盖层居中量同样是归一值
  （`input_overlay_center_x = 0.5`）。
- **按组拖，不逐个拖**：单个按键的位置由 CSS 网格决定，逐个绝对定位会和响应式布局打架。
- **拖动落在 `transform` 上**，不动 CSS 布局，另一组按键不会被挤走。
- **拖动用捕获阶段的 `pointerdown` 拦事件**：摆放模式下按住按键组只是拖动，
  不能同时给游戏发出「方向键按住」，否则角色一路狂奔。前提是**命中元素得是这个组的后代**：
  同一个元素上的监听不分捕获/冒泡，只按注册顺序跑，所以容器自己被子元素铺满
  （`.touch-dpad` 设 `pointer-events: none`，命中交给 `.touch-dpad-hit` 和四个臂），
  这条拦截才真的拦得住。
- **偏移夹在「整组仍在视口内」**，拖不出去；`_measureBase()` 会先摘掉 `transform` 再量基准盒，
  否则每次都基于「已经移动后的位置」算，偏移会越拖越偏。
- 摆放模式临时强制显示手柄时，要**同时**摘掉 `pad-never`、换上 `pad-always`：
  两条 CSS 规则权重相同，只加不换的话「隐藏」仍然生效，进了摆放模式却什么都拖不到。
  退出摆放模式再回到设置里指定的那档。

## 菜单行的值是快照

菜单每行的 `value` 是**建菜单时算好写进数据的**，不是活的绑定。所以点条目之后必须重建数据再画
（`refresh()` 会调 `rebuild()`），只重画一遍（`_render()`）就是把旧文字又画一次 ——
表现为「虚拟手柄的模式真变了，行上还写着自动」。键盘那条路径本来就是 `onSelect → refresh()`，
鼠标点击也统一到 `refresh()`，两条路径不会跑出两种行为。

# 测试方案：什么改动该测到什么程度

定这条的原因：改一个圆角也要等四五分钟，是因为「只有一档测试」—— 浏览器脚本每条都起真浏览器、
打开构建好的页面、等 CSS 过渡走完，串行一遍近 6 分钟。方案的目标是**让测试的成本跟着改动的风险走**，
不是把测试砍掉。

一句话原则：**改样子看样子，改规则测规则，碰共享的东西才跑全量。**

## 三档

| 档 | 什么时候用 | 跑什么 | 实测耗时 |
|----|------------|--------|----------|
| **快** | 改的是**规则**（某个模块的算法、编解码、列表逻辑），且这模块能在 node 里跑 | `npm run test:fast`（3 条脚本 225 条断言，不构建、不起站点） | 约 1 秒 |
| **快（样子）** | 只改某个元素自己的外观（圆角、颜色、间距、字号）或只改文案 | `npm run build` → 我截图放大自己看 → grep 有没有断言引用旧文案 | 约 3 秒 |
| **中** | 改了这个元素的**行为**（点击、显隐、开合、摆位、算位置） | 快档 + 管这个元素的**那一条**脚本 | 30~90 秒 |
| **全** | 碰了共享的东西，或者要提交 / 发布 | `node agent-workspace/run-regression.cjs`（25 条 = 快档 3 + 浏览器 22，约 1000 条断言） | 约 6 分钟，见下面「每条耗时」 |

「共享的东西」= 改一处会波及别处的：`:root` / 大段共用的 CSS 变量、选择器分组
（比如 `.touch-select, .touch-start` 这种一次管好几个元素的）、`--pad-*` 这类手柄材质、
宿主与输入与存储模块、存档格式。

**中间过程允许只跑快档，提交前补一遍全量。** 判错的风险集中在合入那一次暴露，
比每次改动都交全款便宜。

## 改哪个文件 → 跑哪条脚本

浏览器脚本都打 `http://localhost:7890/nes-console/`，也就是**跑在构建产物上**：
改完 `src/` 任何文件都要先 `npm run build`，否则测的是旧页面。

### 样式（`src/styles/global.css`）

| 改的东西 | 归属脚本 |
|----------|----------|
| `.screen .touch-menu`、`.screen .touch-fs`（右上角那颗全屏按钮）、顶栏让位（`--menu-btn-*` / `--topbar-btn-gap` / `--topbar-menu-slot`） | `verify-screen-menu-btn`（两颗按钮的摆位/开合/自带对比，5 种视口：把每层颜色按真实合成顺序压到纯白与纯黑画面上算对比度，还拿手柄的 `--pad-*` 当对照组）、`verify-topbar-align`（顶栏文字与按钮排互不压）；「按得动、不带 `data-action`」在 `verify-touch-xy` |
| `#touch-controls`、`.touch-btn`、`.touch-dpad-group` / `.touch-dpad`（左手块：十字键 + SELECT/START）、`.touch-actions` / `.touch-ab`（右手五键簇，簇心那颗 A+B 键）、`--pad-*` | `verify-touch-controls`、`verify-dpad`（含左右两块配平、拨片顶边与 X/Y 顶边齐平）、`verify-touch-xy`（AB 的摆位、不压到四颗键、一键两动作）；「送到核心」在 `verify-input-reaches-core` |
| 拨片外形的取景框（`.dpad-blade` 的 `stroke-width`，要和 `index.astro` 里 `.touch-dpad-face` 的 `viewBox` 联立才成立） | `verify-dpad`（「描边等粗」「顶边齐平」两条，判的是含描边的可见边） |
| `.toast`（系统提示，画面顶部居中的一次性提示） | `verify-toast` |
| 全局长按抑制（`html, body` 的 `user-select` / `-webkit-tap-highlight-color`、`document` 上拦 `contextmenu`、`app.js` 里那条非 passive 的 `touchstart` 与它的例外名单 `LONG_PRESS_KEEP`） | `verify-touch-xy`（最后一段，52 项）；`-webkit-touch-callout` 只能验构建出的 CSS 文本，例外名单对不对只能用**真实触摸**量（`probe-longpress-scope.cjs`），`.click()` 测不出代价 |
| `.sys-ui` / `.sys-topbar` / `.sys-badge` / `.sys-hintbar`（含左侧 `.sys-count` 数量、右侧 `.sys-hints` 图例）/ 配色变量 `--oz-*` | `smoke-system`、`verify-ozone-colors`、`verify-menu-focus`（`[data-focus]` 门控的高亮框与按键图例）、`verify-toast`（数量在左、图例在右、没数量时整块不占位） |
| `.sys-sidebar`（一级分类栏）与窄屏那条 `@container (max-width: 420px)` 分支 | `verify-sidebar-vertical` |
| `.screen` / `.stage` 的尺寸与自适应 | `test-canvas-sizing`、`verify-canvas-bg` |
| 屏幕外围配色（`--bg-*` / `--accent*` / `--stage-grid` / `--pad-press*`，以及 `.layout-editor` 那几条硬编码青） | `verify-ozone-colors`（末段判「两套色板互不污染」：屏幕内 `--oz-*` 不许被外围的值带跑，外围底色必须不带色相） |
| 菜单行的显隐、返回箭头 | `verify-back-button`、`verify-game-manager`、`verify-control-manager` |

只动上面某一格 → 中档；动了 `--pad-*`、`--oz-*`、`--screen-font` 这类**被多处引用**的变量 → 高档。

### 逻辑（`src/lib/`）

| 模块 | 快档（node，不用浏览器） | 还要跑 |
|------|--------------------------|--------|
| `input-manager.js`、`screen-ui.js`、`settings-manager.js`、`touch-layout.js` | `test-system-core.cjs`（107 条，0.1 秒）—— 菜单的**按键分发**（焦点在分类栏 / 在列表时 ↑↓←→ 与 A/B 各自主张什么）就在这一档验 | 按键链路另跑 `verify-input-reaches-core`；`screen-ui.js` 的 `_renderSidebar`（窄屏分类栏把光标滚进视野）另跑 `verify-sidebar-vertical`；焦点模型的**界面表现**（框落在哪一栏、按键图例换文案、记住位置）另跑 `verify-menu-focus` |
| `nes/rastate.js`（存档容器编解码） | `test-rastate.cjs`（54 条，0.1 秒）：头、块布局、8 字节对齐、往返逐字节、无头档放行、没有 MEM 块报错、跳过 RPLY/ACHV 块 | 真核心产生的状态另跑 `verify-saveload`、`verify-wasm-core` |
| `game-manager.js`（清单、内容哈希、落盘） | `test-game-manager.cjs`（64 条，0.8 秒）：替身是 `fetch` + IndexedDB | 界面按清单显示、列存档不下载 ROM → `verify-rom-catalog` |
| `storage.js`（IndexedDB） | 顺带被 `test-game-manager.cjs` 覆盖了一半（哈希、ROM 落盘、存档删干净）—— 用的是替身库，**真库语义还是要浏览器里验** | `verify-saveload`（全档） |
| `nes/libretro-host.js`、`nes/console.js`、`nes/audio-processor.js` | 不适合（要 wasm + 真音频时钟） | `verify-wasm-core`、`verify-audio-fix`、`smoke-e2e`（全档） |
| `app.js`（接线） | 不适合（整个界面都靠它） | 看接的是哪根线，通常直接全档。快速菜单的条目与「保存 / 读取两行都能 ←/→ 换槽位」在 `smoke-e2e` |

### 别的东西

| 改的东西 | 跑什么 |
|----------|--------|
| `scripts/` 里构建期扫 ROM 的逻辑、往 `public/rom/` 加卡带 | 必须重新 `npm run build` + `verify-rom-catalog` |
| `public/cores/*.wasm`（重新编核心） | 全档，跑不掉 |
| 界面文案（菜单项、提示语） | 快档 + `grep -rn "旧文案" agent-workspace/` 看有没有断言按字符串匹配 |
| 只改 `README.md` / `doc/` | 什么都不用跑 |

## 脚本清单：每条测什么

逻辑测试不依赖浏览器（用最小替身跑模块），只有布局和端到端流程才用真实浏览器。

```bash
node agent-workspace/test-system-core.cjs      # 输入/设置/界面逻辑（107 条，含菜单焦点模型的按键分发）
node agent-workspace/test-rastate.cjs          # 即时存档容器 RASTATE 的读写：头/块布局/8 字节对齐补零/往返逐字节一致/无头档放行/没有 MEM 块报错/能跳过 RPLY 与 ACHV 块（54 条）
node agent-workspace/test-game-manager.cjs     # 游戏列表逻辑：清单地址拼接、内置项字段与补充元数据、同内容不重复、内置排最前、按需下载与缓存、加入即落盘、落盘失败不进列表、恢复、删除连带清存档（64 条，替身：fetch + IndexedDB）
node agent-workspace/verify-wasm-core.cjs      # 核心进产品后的主判据：三款 jsnes 打不开的 ROM 能不能跑、RASTATE 容器结构对不对、存→读→再跑一帧是否逐像素一致、电池存档是否落库、音频有没有溢出
node agent-workspace/smoke-e2e.cjs             # 启动游戏/存档/换槽位/设置全流程（36 条）
node agent-workspace/verify-saveload.cjs       # 存档读写：列表里先起游戏再读、坏存档给得出原因（13 条）
node agent-workspace/verify-audio-fix.cjs      # 音频节点重建：退出再进游戏，AudioContext/Worklet 是否重建、声音计数是否继续往上涨（8 条）
node agent-workspace/verify-pause-on-menu.cjs  # 菜单打开时暂停：读核心自己的帧计数增量判断停没停；含「载入期间按 MENU」那个时间窗（21 条）
node agent-workspace/smoke-system.cjs          # 界面端到端（35 条）
node agent-workspace/verify-menu-focus.cjs     # 菜单焦点模型：开局焦点在分类栏、↑↓ 只动当前那一栏、→/A 进列表、←/B 回分类栏、位置记着、高亮框只有一处、按键图例随焦点换文案（58 条）
node agent-workspace/test-canvas-sizing.cjs    # 画面尺寸（16 种分辨率）
node agent-workspace/verify-canvas-bg.cjs      # canvas 底色
node agent-workspace/verify-rom-catalog.cjs    # ROM 库：扫目录生成清单、清单与磁盘一致、菜单按清单显示、同内容 ROM 不重复、列存档不下载 ROM（21 条）
node agent-workspace/verify-screen-menu-btn.cjs # 屏幕右上角两颗常驻按钮（235 条 = 5 种视口 × 47 条：摆位/开合/按下不位移，外加「双色描边在纯白与纯黑画面上各自 ≥3:1、字和图标对深底 ≥3:1、按下态自己写全了底色与描边」，并拿手柄 A 键的 `--pad-*` 当对照组算一遍它在白画面上 <3:1（说明这两颗不能沿用那套材质）；形状仍是小圆角方块、文字是中文「菜单」，全屏那颗另判不带 `data-action`、菜单关着仍看得见按得着、透明度跟菜单按钮同步）
node agent-workspace/verify-ozone-colors.cjs   # Ozone 配色与对比度（35 条，含「框只在焦点那一栏」，末段判屏幕内/外两套色板互不污染）
node agent-workspace/verify-toast.cjs          # 提示：按键图例只在菜单里、toast 顶部居中播完消失、报错类多停留（2.8s / 6s 两档）、新消息顶掉旧消息并重播动画、长文案换行显示完整不裁切；底栏左下角数量 / 右下角图例各就各位、没数量可说时整块不占位；一级菜单含操作说明与关于（48 条）
node agent-workspace/verify-touch-controls.cjs # 触摸手柄布局（4 种形态）：排布/左右分家/两组中心齐平/离底边 180px/画面离顶 8px（39 条）
node agent-workspace/verify-dpad.cjs           # 十字方向键：形状/与按钮同一套材质和形状/摆位（含左右两块配平、拨片顶边与 X/Y 顶边齐平）/八个扇区/滑动换向/多指并集/斜向进模拟器/摆放模式不发按键（52 条）
node agent-workspace/verify-input-reaches-core.cjs # 按键是否真送到核心：核心查的是单个 id（不是位掩码 256）、按住的键核心读到 1、松开回 0、手柄上 AB 键让核心同时读到 A 和 B 两个位（17 条）
node agent-workspace/verify-touch-xy.cjs       # 触摸手柄 X/Y 与簇心 AB：按得动、界面不靠它们（只用十字键+A/B 能走完存档全流程）、可单独隐藏、不进模拟器；AB 摆在四颗键正中且不压到它们、按住等于 A+B；外加 A 在左 B 在右、长按抑制分四层各自的落点与例外名单（52 条）
node agent-workspace/verify-back-button.cjs    # 子菜单返回按钮（8 条）
node agent-workspace/verify-game-manager.cjs   # 游戏管理菜单（9 条）
node agent-workspace/verify-control-manager.cjs # 控制管理：改绑/显隐/拖动/复位（62 条）
node agent-workspace/verify-topbar-align.cjs   # 顶栏对齐：按钮与标题同行居中、顶栏右端徽标让位给两颗常驻按钮（18 条）
node agent-workspace/verify-sidebar-vertical.cjs # 窄屏一级分类栏：竖排不换向、六项齐、不露滚动条、超出靠上下推、↑↓ 走到底时光标跟着进视野；窄屏详情栏改为排在列表下面且不溢出（33 条，3 种手机视口 + 真起一款游戏）
```

| `test-rastate` / `test-system-core` | 各 0.1 秒 | 快档 |

从这张表能读出三件事：

1. **快档 3 条加起来 1 秒**，是全量的 0.3%。所以纯逻辑的改动没理由不等它。
2. **最贵三条 132 秒，占全量（353.7 秒）近四成**，都贵在同一件事：拿多种视口/多款 ROM 各跑一遍浏览器。
   真要瘦身就从这里动刀（比如视口扫描只在改布局时跑），不是从「砍断言」动刀。
3. **中档的一条脚本普遍 4~29 秒**，等一条比等全量便宜一个数量级 —— 这就是分档的意义。

## 怎么自己判断这次是哪一档

按顺序问三句，第一个「是」就是答案：

1. 改动**只影响这一个元素看起来怎样**，不改变任何行为、不碰共享变量？ → 快档
2. 改动只影响**这一个功能**，别的功能碰不到它的代码？ → 中档（跑它那条脚本）
3. 改动碰了共享变量、选择器分组、宿主/输入/存储、存档格式，或者要提交/发布？ → 全档

判不准就往高一档走，别赌。

## 环境前置与已知假失败

- 预览服务要先起着：`npx astro preview --port 7890 --host`（不加 `--host` 只听 `::1`，
  手机走局域网地址打不开）。
- 无头窗口会被浏览器限流，跑出来的时间曲线全是假的；`lib-browser.cjs` 里已经带了
  三条豁免参数，新写脚本要 `require` 它而不是自己 `chromium.launch()`。
- **批量连跑偶发假失败**：已复现过的有 `verify-dpad.cjs`、`verify-touch-xy.cjs`
  （连跑红、单独跑全绿）。判定为回归前先单独重跑那一条，别急着去改代码找不存在的 bug。
- **`smoke-e2e.cjs` 会整段塌**：连跑时 CPU 被前面的浏览器进程占着，
  「下载 ROM → 编译 wasm → 载卡带 → 出第一帧」这串被挤超时。形状是第一条红在
  「启动后有启动反馈」（状态栏停在「正在加载…」，画布非黑像素 0），后面十几条全是它的连锁 ——
  游戏没起来，快速菜单、存档、读档自然都验不到。
  认这个形状：**开头一条红 + 后面成串红 + 状态栏还停在加载态**，就是环境把启动挤超时了，
  不是流程坏了；反过来，只红一条且游戏确实起来了，才当回归查。
- **`verify-wasm-core.cjs` 的「断音」阈值也属于这一类**：同一款 ROM 连跑时报过断音 7296
  （阈值 < 4096）判失败，单独重跑两次分别 2688 / 更低。原因是连跑时音频线程取数据不及时 ——
  是环境把计数推过了线，不是核心坏了。
- **同一个坑会以「慢」的形式出现**：`verify-saveload.cjs` 连跑时用到过 423.7 秒（平时 20 秒），
  13 条断言一条没红，单独重跑就回到正常。所以看到某条耗时突然涨一个数量级、
  结果却全绿，先按环境处理（单独重跑确认），不要照着这个数去改代码。
- 全量的明细在 `agent-workspace/out/<脚本名>.log`，汇总只留最后几行，
  有失败一定去看明细，那里才有具体数值。

## 快档现在有什么

`npm run test:fast` 跑这 3 条，合计 **225 条断言、约 1 秒**，不构建、不起站点、不碰浏览器：

| 脚本 | 覆盖 | 条数 |
|------|------|------|
| `test-system-core.cjs` | `input-manager.js`、`screen-ui.js`（含菜单焦点模型的分发）、`settings-manager.js`、`touch-layout.js` | 107 |
| `test-rastate.cjs` | `nes/rastate.js`（存档容器的字节格式） | 54 |
| `test-game-manager.cjs` | `game-manager.js` 全部逻辑 + `storage.js` 的哈希、ROM 落盘、存档删除（用替身库） | 64 |

快档测不到的是**真浏览器才有的东西**：`nes/libretro-host.js`、`nes/console.js`、音频时钟、
`app.js` 那堆接线、真 IndexedDB 的语义（替身只按被测代码用到的那几件事实现，替身绿不等于真库绿）、
以及所有 CSS。这些改动该走中档/全档，别拿快档当免检。

**加一条新的快档测试**：文件名 `test-<模块名>.cjs`，放进 `agent-workspace/`，
替身只补被测代码真正用到的那几个 API（不模拟整个浏览器），结尾打 `结果: N 通过, M 失败`，
然后在 `run-regression.cjs` 顶部的 `FAST` 数组里登记一行 —— `npm run test:fast` 与全量都自动带上它。

**加一条新的浏览器档测试**：同样结尾打 `结果: N 通过, M 失败`（runner 靠这行汇总），
文件名 `verify-*.cjs` / `smoke-*.cjs`，在 `run-regression.cjs` 的 `SCRIPTS` 里登记，
并把上面「脚本清单」「改哪个文件 → 跑哪条脚本」两张表一起补上 ——
不登记就等于没测，下一轮改动没人拦。

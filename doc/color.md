# NES 控制台配色参考

本文件记录项目中所有用到的颜色，按区域分组。

### 游戏中半透明背景

游戏中呼出菜单时，背景为半透明渐变（让后面的画面透出来）：

| 位置 | 颜色 | Alpha |
|------|------|-------|
| 顶部 | `rgba(45, 45, 45, 1.0)` | 1.0 |
| 中部 | `rgba(45, 45, 45, 0.94)` | 0.94 |
| 底部 | `rgba(45, 45, 45, 0.75)` | 0.75 |

公式对应 Ozone 默认 `framebuffer_opacity = 0.9`：
- 顶部 alpha = 0.9 / 0.9 = 1.0
- 底部 alpha = 2.5 × 0.9 − 1.5 = 0.75

## 屏幕外（中性石墨 + 一支强调青）

外围刻意只留一个色相：屏幕内是照抄 RetroArch Ozone 的灰 + 青，外围再自带一套颜色
就是两套语言在同一页上打架（原先是「复古未来」的深紫 + 霓虹紫，已整体换掉，
包括从没被引用的 `--nes-*` / `--neon-rose` / `--neon-gold` 那十几条）。

### 背景层次

| 用途 | 颜色 | RGB | 变量 |
|------|------|-----|------|
| 渐变外圈（最深） | `#0B0B0D` | 11, 11, 13 | `--bg-primary` |
| 渐变中心 | `#1A1A1E` | 26, 26, 30 | `--bg-accent` |
| 背景网格线 | `rgba(255,255,255,0.025)` | — | `--stage-grid` |
| 摆放模式工具条底 | `rgba(38,38,43,0.94)` | — | 直接写在 `.layout-editor` |

### 强调色

| 用途 | 颜色 | RGB | 变量 |
|------|------|-----|------|
| 按下描边 / 拖入 ROM 边框 / 摆放框 | `#7FD8F5` | 127, 216, 245 | `--accent` |
| 按下填充 / 主按钮底 | `rgba(89,198,232,0.34)` | — | `--accent-fill` |
| hover 底、1px 细边、虚线框 | `rgba(127,216,245,.18/.5/.85)` | — | 同一支换 alpha |

填充档比 `--accent` 深一档：半透明的提亮色压在近黑底上会发灰，看不出「按下了」。

### 手柄材质

| 用途 | 颜色 | 变量 |
|------|------|------|
| 键的底色（未按下） | `rgba(226,232,240,0.09)` | `--pad-surface` |
| 键的描边 | `rgba(148,163,184,0.45)` | `--pad-line` |
| 描边粗 | `3px` | `--pad-line-w` |
| 按下 | 引用上面的 `--accent-fill` / `--accent` | `--pad-press` / `--pad-press-line` |

方向键四片、六个按键读这一组（描边粗细 `--pad-line-w` 连屏幕内那两颗常驻按钮也共用）。
**屏幕右上角那两颗常驻按钮的底色与描边颜色不在这一组里** —— 它们压在游戏画面上，
背景不可控，得自带对比，见下一节。

### 屏幕右上角两颗常驻按钮（压在画面上，自带对比）

| 用途 | 颜色 | 变量 |
|------|------|------|
| 外圈描边（压在亮画面上起作用） | `rgba(0,0,0,0.9)` | `--btn-ring-out` |
| 内圈描边（压在暗画面上起作用） | `rgba(255,255,255,0.8)` | `--btn-ring-in` |
| 底（深玻璃，浅色字有地方落） | `rgba(8,11,15,0.92)` | `--btn-face` |
| 按下底（强调青压在原深底上的合成值） | `rgba(41,69,79,0.94)` | `--btn-face-press` |
| 按下内圈 | 引用 `--accent` | — |
| 描边粗细 | 仍读 `--pad-line-w`（3px），内圈 1px | — |
| 游戏中整体透明度 | `0.85`（菜单打开时 1） | — |

四档写在按钮自己的规则上（不进 `:root`）：和手柄共享没有意义，改了也不该牵连方向键与动作键。
「一深一浅两条描边」的理由见 `doc/界面与交互.md`「屏幕右上角的两颗常驻按钮」。

## 对比度实测

屏幕内（Ozone）：

| 组合 | 对比度 | WCAG AA |
|------|--------|---------|
| 正文 白 on `#2D2D2D` | 13.77 | ✅ |
| 选中文字 青绿 on `#212227` | 8.72 | ✅ |
| 次要文字 `#9F9FA1` on `#2D2D2D` | 5.21 | ✅ |
| 选中描边 青 on `#212227` | 5.45 | ✅ |

屏幕外（石墨 + 强调青）：

| 组合 | 对比度 | WCAG AA |
|------|--------|---------|
| 强调青 `#7FD8F5` on 渐变中心 `#1A1A1E` | 10.78 | ✅ |
| 强调青 `#7FD8F5` on 渐变外圈 `#0B0B0D` | 12.21 | ✅ |
| 键名文字 `#E2E8F0` on 按下填充（压成 `rgb(47,84,99)`） | 6.63 | ✅ |
| 键名文字 `#E2E8F0` on 未按下底色（压成 `rgb(44,45,49)`） | 11.16 | ✅ |

半透明底色要先和它下面的背景（这里取渐变中心 `#1A1A1E`）合成一个实色再算，
直接拿 `rgba` 里的 RGB 算出来的是错的。按下时文字到 6.63 仍达 AA（正文要求 4.5），
所以键名在按下的瞬间不会糊掉。

屏幕右上角两颗常驻按钮（背景换成「游戏画面可能是任何颜色」的两个极端：纯白与纯黑，
整体透明度 0.85 已经算进合成里）：

| 组合 | 对比度 | 要求 |
|------|--------|------|
| 外圈描边 on 白色画面 | 11.04 | ≥3 ✅ |
| 内圈描边 on 黑色画面 | 9.58 | ≥3 ✅ |
| 内圈描边 on 深底（白画面时） | 7.34 | ≥3 ✅ |
| 内圈描边 on 深底（黑画面时） | 9.12 | ≥3 ✅ |
| 「菜单」/图标 on 深底（白画面时） | 8.70 | ≥4.5 ✅ |
| 「菜单」/图标 on 深底（黑画面时） | 11.54 | ≥4.5 ✅ |
| 按下：内圈（强调青）on 底（白画面时） | 3.78 | ≥3 ✅ |
| 按下：文字 on 底（白画面时） | 4.76 | ≥4.5 ✅ |
| 反例：手柄 `--pad-line` on 白色画面 | 1.38 | ❌ 分不出来 |
| 反例：浅色字 on 手柄 `--pad-surface`（白画面时） | 1.18 | ❌ 字先消失 |

非文本（描边、轮廓）按 WCAG 2.2 SC 1.4.11 要求 ≥3:1，文字按 AA 正文 ≥4.5:1。
两条反例就是「这两颗为什么不沿用手柄材质」的量化理由。
这几行不是手算完就存档了：`verify-screen-menu-btn` 每次跑都从页面读回真实计算值现算现验
（5 种视口 × 每层颜色），失败时把整串数值打出来。

测试文件：`agent-workspace/verify-ozone-colors.cjs`（屏幕内外两套色板）、
`agent-workspace/verify-screen-menu-btn.cjs`（这两颗按钮的对比度）
